# 工作流 — 提好问题和收集上下文

好的设计在第一个像素之前就开始了。两个因素决定制品质量：(1) 你是否理解了用户真正想要的 (2) 你是否收集了将工作扎根于现实的视觉上下文。

## 何时提问 vs 直接构建

| 场景 | 做法 |
|------|------|
| "用附件 PRD 做个 deck" | 提问 — 受众、调性、长度、格式都未定义 |
| "用这个 PRD 做 Eng All Hands deck，10 分钟" | 构建 — 已给够 |
| "把这个截图变成交互原型" | 仅当图片中行为不明确时提问 |
| "做 6 页关于黄油历史的 slides" | 提问 — 太模糊 |
| "给我的外卖 app 做一个 onboarding 原型" | 大量提问 |
| "从代码库重建 composer UI" | 构建 — 源码即需求 |
| "把 CTA 改成海军蓝" | 构建 — 小调整 |

## 问题清单

提问时，一轮覆盖以下内容。一次性 4-10 个聚焦问题比三轮各 2 个快。

### 1. 起点和产品上下文（始终问）

> "我应该从什么开始设计？选项：代码库（我可以读 tokens 和组件）、设计系统/UI kit、当前产品截图、Figma 文件、品牌文档。如果都没有，你想选一个参考品牌作为起点吗？"

### 2. 输出和保真度

- 什么格式？（deck、落地页、可点击原型、动画、海报、线框图、design canvas）
- 什么保真度？（线框 / 中保真 / 高保真）
- 什么平台/视口？（移动端、桌面端、1920×1080 slide、打印、社媒卡片）
- 用途？（演示、交付开发、发布给用户、打印）

### 3. 变体

- 整体流程要几个变体？（1、3、5+）
- 变体在哪个轴上？（流程/UX、视觉风格、文案、动效、颜色、排版）
- 要发散想法还是在单方向上保守变化？
- 有哪些特定屏幕/元素需要多个选项？

### 4. 调性和内容

- 受众是谁？
- 严肃 / 活泼 / 技术 / 编辑 / 安静 / 大声？
- 有文案吗，还是需要我用特定语调写占位文案？

### 5. Tweaks

- 想在设计中能调整什么？（颜色、排版、文案、布局变体、feature flags）
- 浮动 Tweaks 面板可以，还是想看单独的 slides？

### 6. 问题特有（始终再加 3-5 个）

看具体需求生成额外问题。如果你只写了 2-3 个问题，可能缺少问题特有的。推到 8-10 个。

## 收集设计上下文

一旦用户指向代码库/设计系统/Figma：

1. **列出相关文件** — 找到定义设计语言的 5-15 个文件
2. **先读 tokens** — 颜色变量、间距比例、type scale、圆角、阴影
3. **复制需要的资产到项目** — 精准复制，不要批量复制整个组件库
4. **读代表性组件** — 按钮、输入框、卡片、空状态怎么做的
5. **口头描述你看到的** — 简短的"我正在使用的视觉语言：[type scale] / [色板] / [布局节奏]"

## 尽早展示，快速迭代

第一个 HTML 制品应该在前几个工具调用内就出现 — 即使大部分是占位符。把第一次输出当作你和用户讨论的草稿。

好的首次制品模式：

```html
<body>
  <main class="sketchpad">
    <section class="assumptions">
      <h1>设计笔记 — 草稿 v1</h1>
      <p>工作假设：{受众}、{调性}、{平台}。
         视觉系统：{type scale}、{色板}、{布局}。
         计划变体：A（保守，匹配现有）、B（更激进的 type 处理）、C（混合：{隐喻}）。</p>
      <p class="todo">等待：{logo 资产}、{hero 真实文案}。</p>
    </section>
  </main>
</body>
```
